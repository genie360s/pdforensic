# 📄 pdforensic

> Forensic analysis of PDF files: metadata, revision history, recovery of earlier versions, tamper indicators and how the file was produced.

**pdforensic** answers four questions about a PDF:

1. **What does it say about itself?** Info dictionary, XMP, file identifiers, hashes, encryption, signatures, fonts, images, claimed standards (PDF/A, PDF/X, PDF/UA).
2. **Was it changed after it was created?** Every incremental save is found, and the objects each save added, modified or deleted are listed.
3. **What did it look like before?** Each earlier revision is recovered byte for byte.
4. **How was it made?** Exported from Excel or Word, generated by a library such as ReportLab or iText, printed from a browser, scanned, OCR'd, or post-processed by an editor.

It is built on [qpdf](https://github.com/qpdf/qpdf) (through [pikepdf](https://github.com/pikepdf/pikepdf)) for fast, robust parsing, plus a raw byte-level layer for the history that PDF libraries hide. The original [pdfresurrect](https://github.com/enferex/pdfresurrect) C tool is bundled, built from source in `src/pdfresurrect` for Linux, macOS and Windows.

The rules, the clauses of ISO 32000 they rest on, and their limits are written up in [docs/PDF_FORENSICS.md](docs/PDF_FORENSICS.md).

## Install

Requires Python 3.11 or newer. The project is managed with [uv](https://docs.astral.sh/uv/). Wheels are built for Linux (x86_64, arm64), macOS (Apple Silicon) and Windows (x86_64), the platforms pikepdf ships wheels for.

```bash
uv add pdforensic-authentic-check            # as a dependency of your project
uv tool install pdforensic-authentic-check   # or just the command-line tools
```

From source (a C compiler is needed to build `pdfresurrect`; without one the analyzer still works):

```bash
git clone https://github.com/genie360s/pdforensic.git
cd pdforensic
uv sync            # creates .venv, installs the package and the dev tools, builds pdfresurrect
```

## Command line

```bash
pdforensic analyze invoice.pdf            # readable report
pdforensic analyze invoice.pdf --json     # full report as JSON
pdforensic analyze locked.pdf --password secret
pdforensic recover invoice.pdf -o out/    # write every earlier revision
```

Example (a ReportLab invoice whose title was later changed with MuPDF):

```text
PDF version 1.3 (Adobe PDF Reference (PDF 1.3))
Revisions   2    %%EOF markers 2    objects 7    pages 1
Encrypted   no

Metadata (Info dictionary)
  Producer      MuPDF incremental save
  Title         Invoice 0042 (amended)
  ...
Revisions
  1: bytes 0-1385, xref table, +7 ~0 -0 objects
  2: bytes 1385-1807, xref table, +0 ~1 -0 objects
       modified object 5 (Info)

Tamper indicators: level=medium, modified after creation: yes
  [medium] File was saved incrementally 1 time(s) after it was first written
  [low   ] File identifier shows the file changed after creation
  [medium] Producer changed in revision 2
           Revision 1: "ReportLab PDF Library - (opensource)"; revision 2: "MuPDF incremental save".
```

`pdforensic recover` on that file writes `out/<name>-rev1.pdf`, which is identical, byte for byte, to the invoice before it was changed.

## Python

```python
from pdforensic import analyze, recover_revisions, format_report

report = analyze("invoice.pdf")            # a JSON-serializable dict; also accepts bytes
print(format_report(report))

report["structure"]["revision_count"]      # 2
report["revisions"][1]["changes"]          # [{"object": 5, "change": "modified", "type": "Info"}]
report["tamper"]["level"]                  # "none" | "info" | "low" | "medium" | "high"
report["tamper"]["indicators"]             # each with id, severity, title, detail, basis
report["provenance"]                       # tools matched, origin, generation, content_profile

for item in recover_revisions("invoice.pdf", "out"):
    print(item["revision"], item["path"], item["sha256"])
```

Main sections of the report: `file` (size and MD5, SHA-1, SHA-256), `structure`, `encryption`, `identifiers`, `info`, `xmp`, `xmp_history` (the save and conversion events the file records about itself), `conformance_claims`, `revisions`, `signatures`, `pages`, `fonts`, `images`, `features`, `provenance`, `tamper`, `warnings`.

### Reading the result

- Indicators are **evidence, not proof**. A file with no indicators may still have been altered and then fully re-saved ("Save As", "Print to PDF"), which erases its history.
- **Counting `%%EOF` markers is not enough.** A linearized ("fast web view") file has two markers and has never been edited, and so does every PDF exported from Microsoft Word, Excel or PowerPoint; `revision_count` accounts for both.
- `id_mismatch` and `dates_differ` are common in honest files (optimisers, encryption and linearizers all rewrite a file); weigh them with the rest.
- Signature *cryptography* is not verified. The report shows what each signature's byte range covers and whether anything was appended after it.
- A conformance claim (for example PDF/A-1b) is what the file declares, not a validation.

## The pdfresurrect wrappers

The original four functions and commands still work and call the bundled C tool:

| Python | Command | What it does |
|---|---|---|
| `extract_pdf_metadata(path)` | `pdf-meta` | creator information via `pdfresurrect -i` |
| `recover_pdf_versions(path)` | `pdf-recover` | writes versions via `pdfresurrect -w` into `<name>-versions/` |
| `check_no_of_versions(path)` | `pdf-versions` | number of versions via `pdfresurrect -q` |
| `count_pdf_eof_markers(path)` | `pdf-eof` | number of `%%EOF` markers |

pdfresurrect does not decode cross-reference streams or XMP and stops on some linearized files; `analyze` covers those cases. See [src/pdfresurrect/UPSTREAM.md](src/pdfresurrect/UPSTREAM.md) for the vendored version, the portability patches and known limits.

### Building pdfresurrect on its own

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
./build/pdfresurrect -q file.pdf          # build\Release\pdfresurrect.exe on Windows
```

The Python package looks for the binary in this order: the `PDFRESURRECT` environment variable, the copy installed with the package, `build/`, then the `PATH`.

## Tests

```bash
uv run pytest
uv run ruff check .
```

- **Unit**: the raw parser and revision logic (`tests/test_raw.py`), every indicator and the provenance table (`tests/test_forensics.py`).
- **Integration**: the command line end to end (`tests/test_cli.py`) and the compiled C tool with its wrappers (`tests/test_pdfresurrect.py`).
- **Regression**: the full report of every fixture is compared with a stored copy (`tests/test_regression.py`). After an intended change, regenerate with `PDFORENSIC_UPDATE_GOLDEN=1 uv run pytest tests/test_regression.py` and review the diff.
- **Robustness**: thousands of deliberately damaged files must never crash the analyzer (`tests/test_fuzz.py`).
- **Your own files**: `PDFORENSIC_CORPUS=/path/to/pdfs uv run pytest tests/test_corpus.py` runs the analyzer over any folder and checks page counts against qpdf. It has been run on the [BFO PDF/A test suite](https://github.com/bfocom/pdfa-testsuite), the [veraPDF corpus](https://github.com/veraPDF/veraPDF-corpus), the PDF Association's [pdf-differences](https://github.com/pdf-association/pdf-differences) and PDF 2.0 examples, and the Ghent PDF Output Suite.

## Releasing

Pushing a tag such as `v0.2.0` runs `.github/workflows/release.yml`: it builds `pdfresurrect` for Linux, macOS and Windows, builds the wheels and the sdist, and creates a GitHub release with all of them. Publishing to PyPI is off until you set the repository variable `PUBLISH_TO_PYPI` to `true` and configure PyPI trusted publishing for the `pypi` environment.
