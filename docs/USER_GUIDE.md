## 1. What pdforensic does

You give it a PDF. It reads the file's internals and tells you:

- **What the file says about itself**: title, author, the program that made it, creation and modification dates.
- **Whether it was changed after it was first created**, and what changed each time it was saved.
- **What it looked like before**: if earlier versions are still inside the file, it can write them out for you to open.
- **How it was made**: exported from Word or Excel, generated by software, printed from a browser, scanned, and so on.
- **Whether a digital signature still covers the whole file**, or something was added after signing.

Why this works: when many programs save changes to a PDF, they do not rewrite the file. They add the changes to the end and keep the old content. The old version stays inside the file, and pdforensic can find it.

### What it cannot do

Read this before relying on a result.

- **It gives evidence, not a verdict.** A finding means "this deserves a closer look", not "this is forged".
- **A clean result does not prove a file is original.** Someone can edit a PDF and then use "Save As" or "Print to PDF". That writes a brand-new file with no history in it.
- **It does not check that a digital signature is genuine.** It tells you what the signature covers. Use a PDF reader such as Adobe Acrobat to verify who signed.
- **The information a PDF gives about itself can be typed in by anyone.** An author name or a date is a claim, not a fact.

## 2. Install it

pdforensic is installed with **uv**, a free tool that also fetches Python for you. You need Windows, macOS or Linux and an internet connection.

### Step 1: open a terminal

- **Windows**: press the Windows key, type `PowerShell`, press Enter.
- **macOS**: press Command + Space, type `Terminal`, press Enter.
- **Linux**: open your terminal application.

### Step 2: install uv

Copy the line for your system, paste it into the terminal and press Enter.

Windows:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

macOS and Linux:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Close the terminal and open a new one so it notices uv.

### Step 3: install pdforensic

```bash
uv tool install pdforensic-authentic-check
```

### Step 4: check that it worked

```bash
pdforensic --version
```

You should see `pdforensic` followed by a version number. If you see "command not found", run `uv tool update-shell`, open a new terminal and try again.

### To update or remove it later

```bash
uv tool upgrade pdforensic-authentic-check
uv tool uninstall pdforensic-authentic-check
```

### Try it without installing

```bash
uvx --from pdforensic-authentic-check pdforensic analyze invoice.pdf
```

## 3. Check a PDF

Type `pdforensic analyze`, a space, then the location of your file:

```bash
pdforensic analyze invoice.pdf
```

**Tip:** you do not have to type the location. Type `pdforensic analyze ` (with the space), then drag the PDF from your file manager into the terminal window, and press Enter.

If the file name has spaces, put it in quotes: `pdforensic analyze "my invoice.pdf"`.

Your PDF is only read. pdforensic never changes it and never sends it anywhere.

## 4. Understand the result

Here is the full result for a small invoice that was created by a billing program and never touched again.

```text
File        invoice.pdf (1385 bytes)
SHA-256     830b0ab2dfa53f0b6cdc3f0359af23c4b86295e0e87984aeb6686167662d0fb9
PDF version 1.3 (Adobe PDF Reference (PDF 1.3))
Revisions   1    %%EOF markers 1    objects 7    pages 1
Encrypted   no

Metadata (Info dictionary)
  Author        Billing System
  CreationDate  D:20000101000000+00'00'
  Creator       anonymous
  Keywords
  ModDate       D:20000101000000+00'00'
  Producer      ReportLab PDF Library - (opensource)
  Subject       unspecified
  Title         Invoice 0042
  Trapped       /False

Provenance   origin=library  generation=programmatic  content=text
  - Info Producer "ReportLab PDF Library - (opensource)" matches ReportLab (Python library)

Revisions
  1: bytes 0-1385, xref table, +7 ~0 -0 objects

Tamper indicators: level=none, modified after creation: no evidence
  none found
```

Going through it from the top:

| Line | What it means |
|---|---|
| `File` | The file and its size. |
| `SHA-256` | A fingerprint of the file. If even one character of the file changes, the fingerprint changes. Two files with the same fingerprint are identical. Keep it if you need to show later that a file was not altered after you examined it. |
| `PDF version` | The edition of the PDF format the file uses. |
| `Revisions` | **How many times the file was saved in a way that left a trace.** `1` means it has only its original version inside. |
| `pages` | Number of pages. |
| `Encrypted` | Whether the file is password-protected. |
| `Metadata` | What the file says about itself. `Creator` is the program the document was written in, `Producer` is the program that turned it into a PDF, `CreationDate` and `ModDate` are when it was created and last modified. Dates read as year, month, day, hour, minute, second: `D:20000101000000` is 1 January 2000 at 00:00:00. |
| `Provenance` | The tool's best reading of how the file was made, with the reason underneath. See [the table below](#how-the-file-was-made). |
| `Revisions` list | One line per saved version. `+7 ~0 -0 objects` means 7 building blocks added, 0 changed, 0 deleted. |
| `Tamper indicators` | **The summary.** `level` is the most serious finding; the findings are listed below it. |

### The same invoice after someone changed it

Now the same file after its title was changed with an editing tool:

```text
Revisions   2    %%EOF markers 2    objects 7    pages 1
...
  Producer      MuPDF incremental save
  Title         Invoice 0042 (amended)
...
Provenance   origin=editor  generation=post_processed  content=text
  - Info Producer "MuPDF incremental save" matches PDF manipulation library or tool

Revisions
  1: bytes 0-1385, xref table, +7 ~0 -0 objects
  2: bytes 1385-1807, xref table, +0 ~1 -0 objects
       modified object 5 (Info)

Tamper indicators: level=medium, modified after creation: yes
  [medium] File was saved incrementally 1 time(s) after it was first written
           Revisions [2] append changes that are not signature-related. Each earlier revision can be recovered byte-for-byte. (ISO 32000-1 7.5.6)
  [low   ] File identifier shows the file changed after creation
           ...
  [medium] Producer changed in revision 2
           Revision 1: "ReportLab PDF Library - (opensource)"; revision 2: "MuPDF incremental save". (ISO 32000-1 14.3.3)
  [info  ] Metadata names a PDF editing or manipulation tool
           Info Producer "MuPDF incremental save" (heuristic)
```

What this tells you, in plain words:

- The file now holds **2 revisions**: the original and one later save.
- The second save **modified one thing**: the block that holds the title and other details (`Info`).
- The original was made by one program (ReportLab) and the change was made by a different one (MuPDF).
- The overall level is **medium**, and "modified after creation" is **yes**.

Each finding is followed by its detail and, in brackets, the rule it rests on: either a clause of the PDF standard or the word "heuristic" for an educated guess.

### The levels

| Level | Read it as |
|---|---|
| `none` | Nothing was found. Not proof the file is original (see [what it cannot do](#what-it-cannot-do)). |
| `info` | Worth knowing; normal in ordinary files. |
| `low` | Shows the file was written more than once or is slightly unusual. Common in honest files: any program that compresses, protects or optimises a PDF causes it. |
| `medium` | The file was changed after it was created, or its structure is damaged. Look at what changed. |
| `high` | Something was added after a digital signature, or a signature was removed. Take this seriously. |

A sense of proportion: in a set of about 930 everyday PDFs from one computer, roughly half showed no finding, about a third were `low`, 8% were `medium` and two files were `high`.

### How the file was made

`origin` is the kind of program named in the file. `generation` is how the PDF came about.

| generation | Meaning |
|---|---|
| `exported_from_application` | Saved or exported from a program a person works in: Word, Excel, PowerPoint, LibreOffice, InDesign, LaTeX and others. |
| `programmatic` | Generated by software with no person laying it out: invoices, statements, tickets and reports from a system. |
| `browser_print` | Printed or saved as PDF from a web browser. |
| `print_to_pdf` | Made with "Print to PDF" or a similar converter. |
| `scan` | Came from a scanner or a scanning app. |
| `scan_or_image_conversion` | Every page is a picture with no real text: a scan, a photo, or an image saved as PDF. |
| `post_processed` | A PDF editing or signing tool is the only program named. |
| `unknown` | The file does not say. |

`content` describes the pages themselves:

| content | Meaning |
|---|---|
| `text` | Real text you can select and search. |
| `image_only` | Pictures of pages; no text. |
| `image_with_hidden_text` | Pictures of pages with invisible text on top, which is what text recognition (OCR) produces. |
| `mixed` | Some pages of each kind. |

A PDF does not record what it was converted *from*. A spreadsheet exported from Excel says "Excel"; a CSV file opened in Excel and exported also says "Excel".

## 5. Get back an earlier version of a PDF

If `Revisions` is 2 or more, the earlier versions are still inside the file. To write them out:

```bash
pdforensic recover invoice-edited.pdf
```

```text
revision 1  1385 bytes  sha256 830b0ab2dfa5...  invoice-edited-revisions/invoice-edited-rev1.pdf
```

A new folder appears next to where you ran the command, named after your file with `-revisions` added. Inside is one PDF per earlier version: `...-rev1.pdf` is the original, `...-rev2.pdf` the next save, and so on. Open them in any PDF reader and compare them with the current file.

Each recovered file is exactly the file as it was saved at that moment, down to the last byte. In the example, the fingerprint of the recovered `rev1` is the same as the fingerprint of the original invoice shown in part 4.

Options:

| You type | What happens |
|---|---|
| `pdforensic recover file.pdf -o my-folder` | Puts the versions in `my-folder`. |
| `pdforensic recover file.pdf --all` | Also writes a copy of the current version. |

If the file has only one revision you will see: `The file has a single revision; nothing to recover.`

## 6. Common situations

### The PDF asks for a password

```bash
pdforensic analyze statement.pdf --password "the password"
```

Many "protected" PDFs open without a password and only restrict printing or copying. pdforensic reads those with no password needed. If a password is needed and you do not give it, the report says `Encrypted   yes, NOT decrypted (password required)` and shows only what can be seen from outside.

### "Is this a scan?"

Look at the `Provenance` line. `content=image_only` or `content=image_with_hidden_text` means the pages are pictures.

### "Was anything added after it was signed?"

Signed files show a `Signature` line, for example:

```text
Signature    object 7, adbe.pkcs7.detached, signed revision 1, covers whole file: True (cryptography not verified)
```

`covers whole file: True` means nothing was added after signing. If it says `False`, the findings explain what came afterwards. Adding a second signature or the data needed to check a signature years later is normal and is reported as `info` or `low`; ordinary content added after a signature is reported as `high`.

### "The file claims to be PDF/A"

A line such as `Claims      PDF/A-1b (ISO 19005-1, not validated)` shows the standard the file says it follows. pdforensic reports the claim; it does not test whether the claim is true. Use [veraPDF](https://verapdf.org) to validate.

### Checking many files

On macOS and Linux:

```bash
for f in *.pdf; do pdforensic analyze "$f" > "$f.report.txt"; done
```

On Windows (PowerShell):

```powershell
Get-ChildItem *.pdf | ForEach-Object { pdforensic analyze $_.FullName > "$($_.FullName).report.txt" }
```

Each PDF gets a text report beside it.

## 7. What every finding means

The first column is the name used in the report's data (part 8). The printed report shows a sentence instead; the "you will see" column has its opening words.

### About changes to the file

| Name | Level | You will see | In plain words |
|---|---|---|---|
| `incremental_updates` | medium, or info | "File was saved incrementally..." | The file was saved again after it was first written, and the earlier version is still inside. It is `info` when every later save only added a signature or signature-checking data. |
| `tool_changed_between_revisions` | medium | "Producer changed in revision..." | A later save was made with a different program than the original. |
| `deleted_objects` | low | "Objects were deleted in a later revision" | Something was removed in a later save. The removed content is still in the file and comes back when you recover the earlier version. |
| `unreferenced_objects` | low | "Objects exist that no cross-reference section points to" | Left-over content the current document no longer uses. Often left behind by tools that stamp or re-save a file. |
| `id_mismatch` | low | "File identifier shows the file changed after creation" | The file carries two ID numbers that start out equal and differ once the file is written again. Very common in honest files. |
| `permanent_id_changed` | medium | "Permanent file identifier differs between revisions" | The ID that should never change did change between saves. |
| `linearization_stale` | info | "File was changed after it was linearized" | The file was prepared for fast web viewing and then added to. |

### About dates and descriptions

| Name | Level | You will see | In plain words |
|---|---|---|---|
| `dates_differ` | low, or info | "Metadata records a modification after creation" | The modification date is later than the creation date. `info` if the gap is 5 seconds or less. |
| `moddate_before_creation` | low, or info | "ModDate is earlier than CreationDate" | The file says it was modified before it was created. `info` if the gap is under a minute, which some programs produce on their own. |
| `future_date` | low | "... is in the future" | A date in the file has not happened yet. |
| `info_xmp_mismatch` | low, or info | "Info ... and XMP disagree" | A PDF stores its description twice. The two copies do not match. |
| `info_newer_than_xmp` | medium, or info | "Info ModDate is later than the XMP metadata date" | One copy of the description was updated and the other was not: the file was saved again by a program that only knows about one of them. `info` when the gap is a whole number of hours, which is a time-zone mistake. |
| `xmp_history` | info | "The XMP metadata records ... event(s)" | The file keeps its own log of when it was created, converted and saved, and by which program. |
| `editing_tool_named` | info | "Metadata names a PDF editing or manipulation tool" | A program whose job is to edit, merge or modify PDFs is named in the file. |

### About digital signatures

| Name | Level | You will see | In plain words |
|---|---|---|---|
| `content_after_signature` | high, low, or info | "Signature ... does not cover the whole file" | Something was added to the file after it was signed. `high` when what was added is ordinary content; `low` when it is covered by a later signature; `info` when it is only signature-checking data. |
| `signature_removed` | high | "Signature ... is no longer part of the document" | A signature is still inside the file, but the current document no longer uses it. |
| `signature_byte_range_unusual` | medium | "Signature ... has an unusual /ByteRange" | The part of the file the signature covers is not the normal shape. |
| `preflight_ticket` | info | "The file carries a preflight ticket" | A print-industry quality check was recorded in the file, with its result. |
| `preflight_ticket_unsealed` | low | "The preflight ticket is not sealed by its signature" | That record is present without the signature that is supposed to protect it. |

### About the file's structure

| Name | Level | You will see | In plain words |
|---|---|---|---|
| `structural_damage` | medium | "qpdf had to repair the file's structure" | The file's internal index was wrong and had to be rebuilt. Caused by damage, a cut-off download, or editing by hand. |
| `xref_unreadable` | medium | "Cross-reference data could not be read" | Part of the internal index is missing or points nowhere. |
| `xref_offset_mismatch` | medium | "Cross-reference entries point to the wrong place" | The internal index says a piece of content is somewhere it is not. |
| `syntax_warnings` | info | "The file departs from the PDF syntax in small ways" | Small faults that PDF readers tolerate. This describes the program that wrote the file. |
| `trailing_data` | low | "Data follows the final %%EOF marker" | Something is stored after the point where the PDF officially ends. |
| `unknown_pdf_version` | low | "The file declares a PDF version that was never published" | The file claims a version of PDF that does not exist. |
| `version_downgraded` | low | "Revision ... lowers the PDF version" | A later save lowered the file's PDF version, which the standard does not allow. |
| `nonstandard_filter` | low | "Streams use a filter the PDF standard does not define" | Part of the file is packed in a way no standard PDF software can unpack, so it cannot be inspected. |

## 8. Save the report or use it in other software

To save the readable report to a file:

```bash
pdforensic analyze invoice.pdf > invoice-report.txt
```

To get every detail in a form other programs can read (JSON):

```bash
pdforensic analyze invoice.pdf --json > invoice-report.json
```

The JSON report has these sections:

| Section | Contents |
|---|---|
| `file` | Location, size, and MD5, SHA-1 and SHA-256 fingerprints. |
| `engine` | Versions of pdforensic and of the libraries it used, so a result can be reproduced. |
| `structure` | PDF version, number of revisions, number of objects, whether the file is linearized or a hybrid-reference file, bytes after the end, non-standard filters. |
| `encryption` | Whether the file is encrypted, how, and whether it could be opened. |
| `identifiers` | The file's two ID numbers and whether they are equal. |
| `info`, `info_dates` | The file's description of itself, and its dates in a standard form. |
| `xmp`, `xmp_history` | The second copy of the description, and the file's own log of events. |
| `preflight_ticket` | The print-industry check record, if there is one. |
| `conformance_claims` | Standards the file says it follows (PDF/A, PDF/X, PDF/UA, PDF/E, PDF/VT). |
| `revisions` | One entry per saved version: where it starts and ends, its fingerprint, its description, and each object it added, modified or deleted. |
| `signatures` | Each signature: signer name, date, what it covers, which revision it signed. |
| `pages` | Page count and, per page, whether it holds text, images or both. |
| `fonts`, `images` | Fonts and images used. |
| `features` | Forms, JavaScript, attachments, links, bookmarks, accessibility tagging. |
| `provenance` | How the file was made, with the evidence. |
| `tamper` | `level`, `modified_after_creation`, and the list of findings. Each finding has `id`, `severity`, `title`, `detail` and `basis`. |
| `warnings` | Problems met while reading the file. |

### Exit codes

`0` means the report was produced. `2` means the file could not be read (missing, or not a PDF). The exit code does **not** depend on what was found; read `tamper.level` in the JSON for that.

## 9. Use it from Python

Add it to a project:

```bash
uv add pdforensic-authentic-check
```

```python
from pdforensic import analyze, recover_revisions, format_report

report = analyze("invoice.pdf")              # a file path, or the file's bytes

print(format_report(report))                 # the same text the command prints

if report["tamper"]["modified_after_creation"]:
    print("Changed after creation, level:", report["tamper"]["level"])
    for finding in report["tamper"]["indicators"]:
        print(finding["severity"], finding["id"], "-", finding["title"])

for revision in report["revisions"]:
    print(revision["revision"], revision["objects"], revision["changes"])

print(report["provenance"]["generation"])    # for example "programmatic"

# Write earlier versions to a folder
for item in recover_revisions("invoice.pdf", "earlier-versions"):
    print(item["revision"], item["path"], item["sha256"])

# A password-protected file
report = analyze("statement.pdf", password="the password")
```

| Function | What it does |
|---|---|
| `analyze(source, password="")` | Returns the report as a dictionary. `source` is a path or bytes. Raises `PdfError` if the data is not a PDF. |
| `format_report(report)` | Turns a report into readable text. |
| `recover_revisions(source, out_dir=None, include_current=False, password="")` | Writes earlier versions to `out_dir` and returns a list with `revision`, `path`, `size` and `sha256` for each. |

The report can be saved with `json.dumps(report)`.

## 10. The older pdfresurrect commands

pdforensic began as a wrapper around [pdfresurrect](https://github.com/enferex/pdfresurrect), a small program written in C, and still includes it. These four commands and functions are kept for people who already use them. For new work, `pdforensic analyze` and `pdforensic recover` do more and handle more kinds of PDF.

| Command | Python function | What it does |
|---|---|---|
| `pdf-versions file.pdf` | `check_no_of_versions(path)` | Prints how many versions pdfresurrect finds. |
| `pdf-meta file.pdf` | `extract_pdf_metadata(path)` | Prints the creator information pdfresurrect finds. |
| `pdf-recover file.pdf` | `recover_pdf_versions(path)` | Writes versions into a `<name>-versions` folder. |
| `pdf-eof file.pdf` | `count_pdf_eof_markers(path)` | Counts the `%%EOF` end markers in the file. |

Two cautions:

- **Do not judge a file by its number of `%%EOF` markers.** Files prepared for fast web viewing and every PDF exported from Microsoft Word, Excel or PowerPoint have two markers and have never been edited. Use the `Revisions` number from `pdforensic analyze` instead.
- pdfresurrect cannot read some modern PDFs (those with compressed internal indexes) and stops on some files prepared for fast web viewing.

## 11. When something goes wrong

| What you see | What to do |
|---|---|
| `command not found: pdforensic` | Run `uv tool update-shell`, then open a new terminal. If uv itself is not found, repeat step 2 of the installation. |
| `No such file or directory` | The location of the file is wrong. Drag the file into the terminal instead of typing it, and put quotes around names with spaces. |
| `not a PDF: no %PDF-M.m header in the first 1024 bytes` | The file is not a PDF, whatever its name says. |
| `Encrypted   yes, NOT decrypted (password required)` | Add `--password "..."`. |
| `Warning: qpdf could not open the file ...` | The file is too damaged to read fully. The report shows what could still be seen. |
| `pdfresurrect binary not found` | Only affects the four older commands on systems where the small C program could not be built. `pdforensic analyze` and `pdforensic recover` do not need it. |
| The result is `none` but you know the file was edited | It was probably re-saved as a new file, which removes the history. See [what it cannot do](#what-it-cannot-do). |

To report a problem or ask a question: https://github.com/genie360s/pdforensic/issues

## 12. Words used in this guide

| Word | Meaning |
|---|---|
| **Revision** | One saved state of the file. The original is revision 1. |
| **Incremental update** | A save that adds changes to the end of the file and keeps the old content. |
| **Metadata** | Information about the document rather than its content: title, author, dates, the programs used. |
| **Info dictionary** | The older of the two places a PDF stores its metadata. |
| **XMP** | The newer place a PDF stores its metadata. |
| **Producer** | The program that wrote the PDF file. |
| **Creator** | The program the document was written in before it became a PDF. |
| **Object** | One building block of a PDF: a page, a font, an image, a block of text. |
| **Cross-reference table (xref)** | The file's internal index, which says where each object is. |
| **Fingerprint (hash, SHA-256)** | A short code calculated from a file. Any change to the file changes the code. |
| **Digital signature** | A cryptographic seal over the file. It shows who signed and lets a reader detect later changes. |
| **Linearized** | Arranged so the first page can be shown while the rest downloads ("fast web view"). |
| **OCR** | Text recognition: software that reads the words in a scanned picture. |
| **PDF/A, PDF/X, PDF/UA** | Stricter kinds of PDF for archiving, printing and accessibility. |
| **Provenance** | Where something came from and how it was made. |

For the technical background, the rules behind each finding and the sources they rest on, see [PDF_FORENSICS.md](https://github.com/genie360s/pdforensic/blob/main/docs/PDF_FORENSICS.md).
